- Email-before-commit on invitations is accepted: a send failure creates nothing; a commit failure after a send leaves only a harmless dead link.

- Materials accepted: PDF, DOCX, PPTX, XLSX, PNG, JPEG (extension + magic bytes/zip structure, 20 MiB). Files are served only through `/api/files/{id}/download` as attachments.
- Faculty-recorded coverage is per section and per published-syllabus node; students see it labelled "Covered in class" (separate from future student completion).
- Announcements are draft -> published -> archived; published ones are locked (archive and re-post).

2026-10-06 (Claude, Milestone 4 defaults; user may overrule):
- Online quiz totals are released automatically on submit; every other result is released explicitly by faculty. A correction never re-releases by itself. Releasing is idempotent (nothing new, no new release).
- Quiz questions are scored all-or-nothing; short answers match exactly after Unicode normalisation, trimming, whitespace collapsing and case folding. No fuzzy or AI matching. Faculty correct single answers with a reason (audited).
- Starting an attempt after the deadline is allowed only when the quiz allows late work; an in-progress attempt that outlives a strict deadline is finalised with its saved answers the next time it is touched, or by faculty "close open attempts" (only after the deadline). Faculty can enter a score for a student who never attempted; a real later attempt replaces it.
- Once attempts exist the answer keys, points, question set, attempt limit and score rule are frozen; wording, explanations, instructions and deadlines stay editable (new revisions, same question keys).
- Activities: PDF only (20 MiB); each upload is a kept version; free replacement before the deadline; after it only the activity late policy for a FIRST submission or a faculty permission (single use, personal, expiring, audited with a reason).
- The gradebook counts only published, non-archived assessments with "counts toward the grade" and a category/period from the published syllabus policy; attendance comes only from the attendance register (an assessment cannot use the "attendance" category). Policy changes that would orphan graded work are refused at syllabus publish.
- Grade calculation follows the plan exactly: category % from earned/possible (optionally 50 + raw/2), period grade from unrounded category values rounded to 2 dp, course grade from the ROUNDED period grades, pass at the policy passing grade (default 75). Missing = pending, recorded zero counts, zero-weight categories never block, excused attendance is left out, late attendance counts the policy fraction (default 0.5).
- Published grades are immutable releases (period midterm/finals/course); any score, attendance, assessment-setting, audience or policy change flags the affected students' published grades for review without touching what students see; faculty republish explicitly. Students only ever receive grade, remark and release number.
- Withdrawn students keep read access to their own attempts, results and published grades but cannot start work or see course content.
- Decimals are returned as JSON numbers and displayed to two places; the pages send scores as strings.

2026-10-06 (Claude, Milestone 5 defaults; user may overrule):
- Retrieval is Postgres full-text (`simple` configuration, no embeddings): chunks of about 2,000 characters with 200 overlap, never crossing a page or slide; at most 8 chunks within a 12,000-character budget. Only current published learning-item revisions are chunked; publishing indexes inside a SAVEPOINT so an indexing failure can never block publishing (the item just has 0 searchable passages, which faculty see).
- A reference link is never study material by itself. Faculty fetch (SSRF-safe, pinned to a checked public address) or paste the text, review it, and approve it; approved text travels into a new draft only while the link is unchanged.
- Study chat: students only, current enrollment, open term, rate limit (10 per minute), questions up to 1,500 characters, history bounded to 6 messages / 4,000 characters, the user message is saved before the provider call and a retry with the same client id is idempotent (never two copies, never two replies). Chat pauses (409 `quiz_in_progress`) while the student has an open quiz attempt in the same subject. Provider failures return fixed safe messages with codes; no provider body or key is ever returned.
- Answers cite sources as [S1]...; tags that do not match retrieved chunks are removed; source links are built from retrieved rows, not model text. When nothing is retrieved the model is not called and a bilingual "not covered" reply is stored.
- AI quiz drafting: faculty owner + open term; 1 to 30 questions (multiple choice with four distinct choices, true/false, short answer); sources must be published, non-archived, same-offering items with chunks; JSON mode; strict validation, any problem rejects everything (422 `ai_output_invalid`, nothing saved); ownership/term/sources are re-checked after the provider call. The result is an unpublished draft flagged `ai_generated`; each question stores its source. Publishing requires `reviewed_counter == draft_counter` (409 `review_required`), so any edit cancels the review, and a new draft of an AI quiz needs a fresh review. Students never receive AI metadata or sources.
- Progress counts only: a lesson the student explicitly marked complete, a quiz attempt the STUDENT submitted (not expiry-by-touch, not faculty "close open attempts"), and each activity upload (distinct event per version, one step per activity). Events are unique per (student, type, ref) so retries cannot inflate counts. Days/weeks are bucketed in Asia/Manila (weeks start Monday); last 14 days and 8 weeks, zero-filled. Completion % is over applicable published, targeted, non-archived lessons + online quizzes + activities; completed work whose step no longer applies stays in history, is excluded from the percentage and is explained to the student. Faculty see counts per student, never chats, answers or scores; progress is not mastery and never touches grades or review flags.
- `ai-check` CLI lists the provider models, then sends English/Filipino/Taglish chat and JSON-mode requests to the CONFIGURED chat and quiz models through the app's own provider code; it refuses to pass on the simulator or without a key, and only suggests `llama-3.3-70b-versatile` when the key can use it. `reindex-chunks` rebuilds chunks for every published revision.
