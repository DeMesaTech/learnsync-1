# Design system

Use reference/dashboard-prototype.html Variant A as a visual reference. Preserve its navy/blue palette, but implement actual routes and permissions. Product navigation must omit demo role/variant switches.

Use semantic CSS variables, system/light/dark themes, base mobile layouts, 640px small and 1024px desktop navigation breakpoints. Verify keyboard focus, contrast, 44px targets and no whole-page horizontal overflow.

Short independent forms use native dialog with accessible labels, focus restoration and unsaved-change protection. Dialog close headers and terminal action groups stay visible while scrolling; contextual labels for editors remain with the header. Imports, syllabus, content editor, quizzes and gradebooks use pages. Server errors and saving/recovery/conflict states must be visible.

Online quizzes have no per-question time-limit controls or countdowns. During an attempt, show one question at a time with an accessible question-number navigator and saved-answer status. Students can navigate freely and edit any answer until submission; quiz availability and deadlines remain visible and enforced.

Detailed colors, route inventory and theme rules: IMPLEMENTATION_PLAN.md section 5.

Prospectus review groups subjects under year-level navigation tabs and semester headings. Rows with unclear placement stay available under Unplaced and remain editable.

## Route map as built (supersedes the inventory in IMPLEMENTATION_PLAN.md section 5)

Several plan routes became tabs of one offering page; this is the actual map (source: `frontend/src/app/router.tsx`).

Public: `/login`, `/forgot-password`, `/reset-password`, `/accept-invitation`. Signed in: `/account`; each role's home `/admin`, `/faculty`, `/student`.

Admin (`/admin/...`): `settings` is the Settings page, focused on creating a school year and two draft semesters, scheduling and activating them, and closing the single active semester. Draft calendars start empty. An inactive semester can be reopened only within its scheduled dates and when no other semester is active; reopening requires a reason and is audited. `students` and `offerings` are independent management pages. Student import opens as a dialog from Student management (the legacy term import URL remains available); faculty import opens as a dialog from Faculty Management, where preview names and emails can be edited and revalidated before commit. The legacy `/admin/teachers/import` URL redirects to Faculty Management. Other established routes include `subjects`, `subjects/import`, `subjects/import/:importId`, `offerings/:offeringId` (roster), `issues` (reports), and `audit`.

Student management retains the **Course** filter label for college/program selection. Sections are owned by one college/program and use its code in generated names (for example, `BSE 1A`); subject offerings are assigned later in the separate Offerings tab.

Faculty (`/faculty/...`): `subjects`, `issues` (report a problem), and per offering `offerings/:offeringId` with tabs `` (students), `setup`, `syllabus`, `content`, `content/:itemId/edit`, `assessments`, `assessments/:assessmentId/edit`, `assessments/:assessmentId/scores`, `attendance`, `gradebook` (publish grades and export), `progress`, `announcements`.

Student (`/student/...`): `subjects`, `issues`, and per offering `offerings/:offeringId` with tabs `syllabus`, `lessons`, `lessons/:itemId`, `study`, `work`, `work/:assessmentId`, `work/:assessmentId/attempts/:attemptId`, `progress`, `results`, `announcements`. A withdrawn student sees only `results`.

Not built (plan items without a page): `/student/progress` across subjects, `/admin/students`, `/admin/sections` pages (sections and students are managed inside the term workspace), and per-kind faculty routes (`quizzes`, `activities`, `examinations` are one `assessments` page).

Added later: student `/student/todo` (all open work) and `/student/study-buddy` (all Study buddy conversations; the per-subject `study` tab now redirects there). Students also get a floating Study buddy button on every page except the Study buddy page and quiz attempts.

Confirmations and undo (Phase 3): confirm only what cannot be undone or what students will see at once (return results, publish grades or an announcement, submit answers, delete or discard a draft, close a term, sign out with unsaved work), always through `useConfirm()` with the safe choice first. Reversible edits (remove a question, a chapter or the grading policy) use `useUndo()`. Never use the browser's `confirm()`.

## Classwork pattern (Phase 5)
- Three levels, each looking different: the subject tabs (underline), a Material category selector matching Faculty Classwork, then a segmented completion filter (soft grey track, white selected segment, All selected by default). Chapters are bold headings with an accent underline; topics are indented under a vertical line.
- Faculty Classwork is a subject content manager with assigned-subject and section selectors, chapter/resource/published/draft counts, a chapter navigator, and chapter-local search/type filters. The selected chapter shows its materials and status; faculty can add material, edit the syllabus, reorder items, and manage drafts/publications. Adding a chapter starts a new unpublished syllabus revision when needed and autosaves chapter/topic edits to that draft; closing the editor flushes pending saves and never publishes.
- In the selected faculty chapter, announcements appear in the same list as materials, ordered newest first by their publication/creation time or the material's current draft update/publication time. Show each row's date so the chronology is clear; keep announcement editing, publishing, and pagination available.
- The syllabus grading policy can allow multiple categories for online quizzes and activities independently. Assessment editors offer only the categories allowed by the published syllabus; the server enforces the rule and prevents publishing a syllabus revision that would invalidate existing graded assessments.
- AI quiz source choices are grouped by syllabus chapter. Provide title search and chapter checkboxes that can narrow to one or combine multiple chapters, with an indeterminate All chapters control; changing filters must not clear chosen materials. Show each chapter's material choices directly below its checkbox. Within each visible chapter, teachers can select individual readable published materials or all matching materials; materials outside chapter anchors remain under Other materials. The chapter Create menu opens above its trigger so the menu stays attached to the action without extending below the chapter.
- In the faculty item editor, syllabus topics that exist only in the unpublished syllabus draft are labeled and cannot be used to publish an item. Provide direct actions to open syllabus setup to publish the existing draft or detach the item from that topic; setup must preserve and edit that draft rather than start another one. The API remains the final guard.
- Student Classwork follows the same content-manager hierarchy, overview cards, responsive chapter navigator, selected-chapter materials layout, and Material category selector as Faculty Classwork. Keep the same category options (`All materials`, `Lessons`, `Quizzes`, `Activities`, `Exams`) and default to All materials when no type is selected. Preserve the `?type=all|lesson|quiz|activity|exam` routes, chapter search, completion filters, results, and next-step states. Search is scoped to the selected type and completion filter. At narrow widths, chapter choices become a horizontally scrollable row above the materials.
- Student lesson, file, and link detail pages do not repeat the Classwork type navigation; retain the in-page Back to Classwork link.
- Student Stream is scoped to the selected subject. Announcements, published materials, released results, and published grades appear together in one newest-first feed; announcement text and dates remain visible, and materials/results keep their links. The weekly completion/submission activity panel remains separate at the bottom. Weekly counts include deliberate learning actions only and use the school's local week.
- Opening a subject from dashboard cards, subject lists, or the sidebar opens its Stream by default for both roles. Explicit links to Classwork, grades/results, progress, and other subject functions continue to open their own pages.
- `components/ClassworkTypes.tsx` remains available for syllabus navigation; Student Classwork's Material category selector uses the same labels and query values as Faculty Classwork without category counts.
- Route map: `/…/offerings/:id/stream | classwork | syllabus | people | grades`; old list addresses redirect into Classwork.
- Faculty Grades stays visible while an offering has no published assessments. From Classwork, choosing a material or assessment creates an unpublished draft with a default title and all-section audience, then opens its editor directly; the editor is where title and audience are changed. Direct assessment edit links remain pages.

## Faculty gradebook
- Keep student search, Section and Period filters, column visibility toggles, and the result count in one compact row on desktop; allow the controls to wrap at narrow viewport widths.
- Render every configured grading-policy category within each period, even when it has no assessments; keep a blank, accessible placeholder column for empty categories.
- Show each category's configured weight in its header and carry the thick accent borders around its columns through the last student row, including empty-category placeholders.
- Place an Add manual grade column icon beside Edit scores in the sticky student-detail header. Its popover asks for title, total score, grading category, and period; new columns are immediately available for score entry and participate in grade calculation.
- Keep PDF and Excel grade exports in an accessible popover beside Ready to publish; include format icons, retain period, section, and published or working scope selection, and include category weights in exported grade summaries.
- Use compact `<<` and `>>` pager controls on the gradebook only; preserve accessible Previous/Next names and the shared pager's text labels on other pages.
- Keep the read-mode Edit scores control in the sticky Section header, or the Student header when Section is hidden. Put its entry instruction in the control tooltip. In edit mode, place the Save/Cancel action bar in one merged sticky header cell above the student-detail headers; its span follows the visible Section and Student number columns.
- Keep assessment titles available as tooltips and accessible names while showing only the maximum points in the compact table header; omit separate assessment-score links from those headers.
- Show a compact, icon-only, accessibly labeled return action with a tooltip in an assessment header when any result is unreleased. Keep its icon at the table-text scale. It opens the existing confirmation before making scores visible to students; do not show it for attendance columns or already-returned results.
- Keep all three Gradebook table-header rows sticky while scrolling scores, including the compact assessment/date header row.
- Add an **Edit grading categories** action to the Gradebook toolbar. It opens the newer subject-setup wizard directly at Grading, reusing an existing draft or creating a recoverable draft from the published syllabus; the published policy remains active until normal review and publication. Disable the action for closed terms and while score edits are unsaved.
- Include recorded attendance dates as read-only Gradebook columns, with headers in `MM/DD/YY` format and the full date in each header tooltip. Each date has a one-point maximum and uses the same raw points as category calculation: present earns 1, absent earns 0, and late earns the configured fraction. Apply the category weight in the period calculation, not by dividing it among dates. Unmarked and excused entries show no points with an explanatory tooltip. These columns are display-only and do not add another score to grade calculation.

## Term offering administration
- The term's Offerings table can be filtered to one teacher when multiple teachers have assignments. Bulk Assign subjects defaults to active subjects placed in that term's semester; an explicit All semesters option remains available for approved exceptions. For a prospectus subject with a year-level placement, the assignment dialog lists only sections in that year.
- Bulk subject assignment identifies the academic term, narrows the workflow to a college/program, then selects one faculty member and one or more subject-section pairs. Selected pairs remain visible as subject cards with section chips and a live assignment total. Keep duplicate checks, year-level filtering, off-semester reasons, and all-or-nothing saving intact.
- In bulk assignment, a subject is unavailable when every eligible section in the selected college/program is already assigned. Sections already assigned to another teacher (including archived assignments, whose section links remain protected by history) are disabled in the subject card; automatically preselected sections include only unassigned sections. The API independently rejects conflicting section assignments with a clear error.
- Admin data tables use compact typography and cell spacing and preserve readable column widths with horizontal scrolling inside their table region rather than compressing columns or causing page-wide overflow. The bulk assignment subject chooser can filter by prospectus year level, including unplaced subjects.
- Admin table rows use reduced vertical padding; inline row actions and their icons are sized to match the compact table typography while retaining clear labels and focus states.
- Faculty Management separates **Teachers** and **Subject assignments** into tabs. The Teachers table displays college/program as text and uses an edit/save/cancel row mode to edit teacher name, email, and college/program without an inline dropdown. Email changes revoke sessions and require a new invitation verification. It provides server-searched teacher accounts and filtering based on `account.college_id`, individual invitations, account activation/deactivation, and confirmation-backed invitation/reset-link sending. Account deactivation preserves teaching and audit history. Teacher invites and editable import previews require a college/program for new accounts. In Subject assignments, the college filter narrows the teacher selector and assignments using the same account `college_id`; it does not infer college from sections currently assigned.
- Faculty Management uses icon-only, accessibly labeled row actions: edit opens a subject-fixed assignment dialog, roster opens in a modal without leaving the page, and Take over transfers an existing assignment to another active teacher. Takeover preserves the offering and its academic records in place and audits the prior and new faculty; duplicate subject assignments are rejected. Archiving an assignment preserves history and allows restoration; active enrollments must be withdrawn before archival. Mouse-wheel vertical scrolling over an overflowing offerings table advances its horizontal scroll position.
- Offerings display one row per subject assignment. Its section and enrollment cells list matching sections/counts together horizontally as individually bordered chips, with a hover- or keyboard-revealed add-section action contained within the section cell. Assignment editing cannot change the faculty member; use Take over to hand the existing assignment and history to another teacher.
- Let the Faculty Management offerings table fit its content using automatic column sizing; keep horizontal scrolling contained within the table region when it exceeds the viewport.

## Replacing a syllabus
- On a published syllabus, make “Replace syllabus from a file” available as a DOCX/PDF import. Import creates a reviewable draft; keep the published revision and its grading policy live until faculty publishes the replacement. Preserve the existing grading policy in the imported draft.
- Chapter outline editing contains the chapter title, time allotment, and topics only. Assessments are authored as separate assessment records, not as chapter metadata.

## Feedback toasts and celebration
Use `useToast()` for a one-line result of an action that is not already obvious from the page (plain, 5 seconds) and `useUndo()` for something that can be put back (Undo, 10 seconds). One toast at a time, bottom left. `celebrate()` is only for a finished lesson or quiz.

## File and link pages
A file page shows the PDF in a frame or the picture inline (never anything else), then a Download button with the size; a link page is a card with the site name, the teacher's note, one "Open the link" button that opens a new tab with `rel="noopener noreferrer"`, and the address in small text. All three kinds end with the same "Mark lesson / file / link as complete" button and the same Next item.
